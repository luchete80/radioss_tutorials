# Model 4: A2024-T351 cutting case

`model_0000.rad` starts from the model 3 starter deck. The tool's 196 `/BRICK/2` nodes were first raised by `1.0e-4 m` with `transform_tool.py` (`--angle-deg 0 --dy 0.0001 --part 2`). A subsequent affine XY map about the tool tip sets the two cutting-face orientations to the requested rake and clearance angles while holding the tip fixed. The second step is reproducible with `adjust_tool_angles.py`; first regenerate the translated deck, then run the script on that intermediate file. The workpiece was rebuilt from its matching `z=0` and `z=0.0002 m` outer faces, with each projected XY cell subdivided 2x2. The deck now has one brick layer through Z and 63,000 workpiece bricks. `refine_workpiece.py` reproduces this operation and backs up the input before writing. `model_0001.rad` is the unchanged model 3 engine deck. Model 3 files were not modified.

## Geometry and mesh audit

- The workpiece top is at `y=0.0050 m`; the tool tip was at `y=0.0045 m` and is now at `y=0.0046 m`. The resulting vertical uncut chip thickness is `0.0004 m` (0.4 mm).
- The original mesh's two cutting-face directions were measured as rake `21.31°` and clearance `1.31°`. The affine map sets these to `17.5°` and `7°`, holding the raised tip `(x,y)=(0,0.0046 m)` fixed. For reproducibility, it maps vectors `u=(-sin 21.3098°, cos 21.3098°)` and `v=(-cos 1.3087°, sin 1.3087°)` to `U=(-sin 17.5°, cos 17.5°)` and `V=(-cos 7°, sin 7°)` using `M=[U V][u v]^-1`, where `M=[[0.9942918802, 0.0650799704],[-0.0994002110,0.9849347548]]`. It changes the tool mesh shape slightly (determinant `0.98578`) and may affect local element quality; there is no remeshing or quality check in this delivery.
- The workpiece is a 3D brick mesh, not a shell with a `/PROP` thickness field. Its original 47,250 bricks had three elements through Z. The refined mesh has one element through Z, retains the `0.2 mm` outer-surface separation, and contains `63,000` bricks. A static edge-length audit near the cut gives `0.0387–0.0423 mm` with median `0.0399 mm`; this is finer than the input, though still coarser than the `~0.03 mm` target.
- Tool motion is `800 m/min = 13.3333333333 m/s` in `/FUNCT/1`. The original ramp timing is retained.

## Boundary and contact audit

`/BCS/1` (`111`, group 1) fixes translations on the existing `y=0` workpiece end face. The updated group covers all refined nodes on that face. `/BCS/4` (`001`, group 4) fixes Z motion on the original outer faces `z=0` and `z=0.0002 m`; both faces remain represented and group 4 contains all nodes in the one-layer mesh. Consequently every workpiece node is Z-constrained in the reduced one-layer topology, giving plane-strain-like through-thickness kinematics. This follows from retaining the existing two-face Z constraint while removing interior Z layers; it is not a newly added BC, but it is a material modeling consequence to keep in mind. `/BCS/5` and tool group 5 remain unchanged.

`/INTER/TYPE7/1` still uses node group 102 as the slave set and the `/SURF/PART/EXT/2` surface as the master; that surface references tool part 2. Group 102's original workpiece membership was transferred by topological interpolation: a new edge/face node is added only when all of its original support nodes belonged to the group. The group grew from 15,060 to 29,058 nodes and has no nodes outside the workpiece. `/IMPVEL/1` still prescribes X motion through group 103, which remains the same 196 tool nodes. The contact and tool-motion references were not changed.

Static verification and exact before/after counts are in [AUDITORIA_MALLA.md](AUDITORIA_MALLA.md). The pre-refinement input is preserved as `model_0000.rad.before_xy_refine`.

## Material and provenance

The requested AA2024-T351 density, elastic constants, Johnson-Cook flow parameters, failure parameters, and melting point are entered in SI units. A suitable public source was found, but no thesis file was present in this workspace: Saleem et al., [Computational Analysis and Artificial Neural Network Optimization of Dry Turning Parameters—AA2024-T351 (2017)](https://doi.org/10.3390/app7060642), reports `rho=2700 kg/m^3`, `E=73 GPa`, `nu=0.33`, `A/B/n/C/m=352/440/0.42/0.0083/1`, `D1-D5=0.13/0.13/-1.5/0.011/0`, `Tm=520°C`, and `Troom=25°C`. Its thermal data are `Cp=0.557*T_C+877.6 J/(kg K)` and `k=0.247*T_C+114.4 W/(m K)` for `25–300°C`, then `k=-0.125*T_C+226` from `300°C` to melt.

The source's flow and damage reference strain rate is `1 s^-1`; see Asad et al., [Dry cutting study of an aluminium alloy (A2024-T351): a numerical and experimental approach (2008)](https://doi.org/10.1007/s12289-008-0150-9), which also describes a fracture-energy-based damage evolution law. The deck uses `1 s^-1` for both `/MAT/PLAS_JOHNS` and `/FAIL/JOHNSON`.

OpenRadioss `/HEAT/MAT` takes a scalar volumetric heat capacity and linear solid conductivity coefficients in this form. Therefore the deck uses `Cp` evaluated at `25°C` (`rho*Cp=2,407,117.5 J/(m^3 K)`) and the first conductivity branch rewritten for Kelvin (`k=46.93195+0.247*T_K`). It does not reproduce temperature-varying heat capacity or the conductivity slope change above `300°C`; the source does not give the required Radioss-specific tabulation or latent heat. The existing tool material values are retained, with its initial temperature aligned to `25°C`.

## Failure-model convention and limitation

The requested `D3=-1.5` is stored verbatim. Altair defines Radioss triaxiality as `sigma_m/sigma_VM` (positive in tension) and failure strain with `exp(D3*sigma*)`; see the [Radioss `/FAIL/JOHNSON` reference](https://help.altair.com/hwsolvers/rad/topics/solvers/rad/fail_johnson_starter_r.htm). Thus `D3=-1.5` makes fracture strain decrease as tensile triaxiality increases. Abaqus' current Johnson-Cook damage-initiation form uses `exp(-d3*eta)` and says this sign differs from the original formula; see [Abaqus damage initiation documentation](https://docs.software.vt.edu/abaqusv2025/English/SIMACAEMATRefMap/simamat-c-damageinitductile.htm). For equivalent equations with the same tension-positive triaxiality, the coefficient has opposite sign between those two forms. The source article reports `-1.5` but does not unambiguously establish the implementation convention used to identify it, so verify that convention before treating the literature parameter as calibrated for a particular solver.

`/FAIL/JOHNSON` accumulates damage to an element failure/deletion condition. It does not implement the paper's subsequent fracture-energy/displacement damage evolution and stress softening. Thus this model contains the requested Johnson-Cook initiation/failure criterion, but does not reproduce the full thesis/article damage evolution. The source's fracture-energy value/model and its exact convention must be recovered before claiming that level of reproduction.
